YouTube Transcript Processing Workflows

Transcript acquisition, model context, analysis, persistence, and observability are separate concerns.

Option 1: API + batch analysis

YouTube URL→ Transcript REST/API→ Normalize cues→ OpenAI

What happens

  • Retrieve the transcript programmatically.
  • Send all text, or bounded chunks, to the model.
  • Validate and persist structured references.

Tradeoff

Simple and deterministic. “Entire transcript in one context window” is optional, not required. Long videos should usually be chunked or summarized first.

Option 2: Model-driven MCP inspection

YouTube URL→ Transcript MCP→ OpenAI

What happens

  • The model calls tools such as get-transcript, list-segments, or search.
  • Data can arrive incrementally or by query.
  • Tool calls and intermediate results are observable.

Important correction

MCP does not automatically prevent context growth. Tool results still enter model context unless the server paginates, searches, summarizes, or stores state externally.

Option 3: API pipeline + MCP observability

YouTube URL→ Transcript API→ Store/index→ OpenAI
MCP audit tools↔ Cues, chunks, references, logs

What happens

  • The application owns the reliable batch workflow.
  • MCP exposes read-only inspection and re-check tools.
  • Humans or agents can inspect intermediate artifacts.

Recommended architecture: hybrid, with API-first execution

Astro UI→ Server/CLI orchestrator→ Transcript provider→ Cue store + chunk index→ OpenAI structured analysis→ Validated Markdown
Optional MCP server↔ read cues / search chunks / inspect candidates / replay checks

Use the API/library path for production because it is easier to type, time out, test, retry, and persist. Use MCP as an optional operator and agent observability layer, not as the primary Astro request boundary.

Context strategy: short transcript → one structured OpenAI request may be fine; long transcript → retrieve once, normalize, persist, chunk, analyze chunks, deduplicate references, then run a final synthesis pass. The MCP layer can inspect every stage without requiring the entire transcript to be loaded into one model call.
